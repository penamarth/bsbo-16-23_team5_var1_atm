# Прецедент: Снять наличные

## Рамки
Бекенд банкомата NextGen: локальное JSON-хранилище, простая проверка остатка и суточного лимита, управление диспенсером без детализации номиналов.

## Уровень
User Goal.

## Основной исполнитель
Клиент (активная сессия банкомата).

## Заинтересованные лица
- **Клиент.** Получить наличные в запрошенной сумме.
- **Банк/оператор.** Учитывать списание и журналировать операцию.
- **Инкассация.** Знать остаток в диспенсере.

## Предусловия
- Сессия активна: `AtmSession` получен через `StartSession(card, pin)`.
- В диспенсере достаточно средств для запрошенной суммы (`CashDispenser.Remaining`).
- Локальное хранилище доступно.

## Постусловия
- **Успех:** сумма списана со счета, дневной расход по счету увеличен, наличные выданы и остаток диспенсера уменьшен, запись `WITHDRAWAL/Success` в `operations.json`.
- **Отказ до выдачи:** баланс/лимит/остаток диспенсера не меняются, запись `WITHDRAWAL/Failed`.
- **Отказ после списания (неудача диспенсера):** средства уже списаны и лимит обновлен, но выдачи не было; журнал `Failed` с причиной "Ошибка диспенсера" (компенсации нет).
- Чек печатается только внешним сценарием через `ReceiptPrinter`.

## Логика банкомата (бекенд)
- `ATMController.Withdraw(session, amount)`:
  - проверяет `CashDispenser.CanDispense`; при `false` логирует `Failed`;
  - вызывает `BankingServiceClient.ExecuteWithdrawal`;
  - при успехе пытается `CashDispenser.TryDispense`; логирует результат.
- `BankingServiceClient.ExecuteWithdrawal`:
  - `amount <= 0` → `false`;
  - проверяет наличие счета и баланса;
  - проверяет суточный лимит `DailyLimit = 10000m` на текущую дату;
  - уменьшает баланс, увеличивает дневное снятие, сохраняет JSON.
- `CashDispenser.TryDispense` уменьшает остаток диспенсера и логирует выдачу.
- `OperationJournal.Add` фиксирует каждое решение (успех/отказ).

## Основной успешный сценарий (backend)
1. Сценарий знает сумму `amount`.
2. Вызывает `ATMController.Withdraw(session, amount)`.
3. Контроллер проверяет остаток диспенсера (`CanDispense`).
4. `BankingServiceClient.ExecuteWithdrawal` списывает со счета и обновляет дневной лимит, сохраняет JSON.
5. `CashDispenser.TryDispense` выдает наличные и уменьшает остаток.
6. `OperationJournal` записывает `WITHDRAWAL / Success`.
7. При необходимости сценарий печатает чек.

## Альтернативы
- `CanDispense == false` → журнал `Failed`, возврат `false`.
- `ExecuteWithdrawal == false` (недостаточно средств / превышен лимит / некорректная сумма) → журнал `Failed`, возврат `false`.
- `TryDispense == false` (механическая ошибка) → журнал `Failed`, но списание уже произошло, возврат `false`.

## Системные операции (факт кода)
- `ATMController.Withdraw(session, amount) : bool` — оркестрация, лог.
- `BankingServiceClient.ExecuteWithdrawal(accountId, amount) : bool` — проверка баланса и лимита, списание, persist.
- `CashDispenser.CanDispense(amount) : bool` — проверка остатка.
- `CashDispenser.TryDispense(amount) : bool` — уменьшение остатка и лог.
- `OperationJournal.Add(OperationEntry)` — запись `WITHDRAWAL`.
- `ReceiptPrinter.PrintReceipt(text)` — опционален, не вызывается контроллером.

## Специальные требования (реализованные/ограничения)
- Суточный лимит: 10 000 рублей (константа в коде), транзакционный лимит не проверяется.
- Начальный баланс счетов: 15 000 рублей при первом появлении карты.
- Номиналы и стратегия выдачи не моделируются; проверяется только общая сумма.
- Нет отката при ошибке диспенсера после успешного списания.

## Частота использования
Высокая по бизнес-смыслу; в демо вызывается один раз.

## Открытые вопросы
- Нужен ли откат/компенсация при сбое диспенсера?
- Следует ли вводить проверку кратности номиналам и лимит за операцию?
- Стоит ли логировать остаток диспенсера в журнал операций?
