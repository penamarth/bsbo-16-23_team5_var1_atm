# Прецедент: Снятие наличных

## Рамки
Система банкомата (ATM) NextGen для обслуживания клиентов банка.

## Уровень
Задача, определенная пользователем (User Goal).

## Основной исполнитель
Клиент банка.

## Заинтересованные лица и их требования

**Клиент.** Хочет быстро и удобно снять наличные деньги со своего счета. Хочет быть уверенным, что сумма правильно списана со счета и выдана полностью. Желает получить чек для подтверждения транзакции. Не хочет превышать установленные лимиты снятия.

**Банк.** Хочет обеспечить безопасность транзакции и предотвратить мошенничество. Заинтересован в точном учете выданных средств. Хочет соблюдать суточные лимиты снятия. Желает минимизировать риск недостачи наличных в банкомате.

**Банковская система.** Хочет получать корректные запросы на списание средств. Заинтересована в проверке достаточности средств на счете и соблюдении лимитов. Хочет зарегистрировать все транзакции для бухгалтерского учета.

**Служба инкассации.** Хочет получать точную информацию о количестве выданных средств для планирования пополнения банкомата.

**Оператор банкомата.** Хочет минимизировать количество жалоб на неправильное списание или выдачу средств.

## Предусловия
- Клиент вставил карту в банкомат
- Клиент успешно прошел аутентификацию (ввел правильный PIN)
- В банкомате достаточно наличных для выдачи
- Банковская система доступна
- На счете клиента есть доступные средства

## Результаты (Постусловия)
- Средства списаны со счета клиента
- Наличные выданы из диспенсера
- Транзакция зарегистрирована в банковской системе
- Остаток наличных в банкомате уменьшен на сумму выдачи
- Суточный лимит снятия клиента обновлен
- Опционально: чек о транзакции распечатан
- Бухгалтерская система обновлена

## Логика банкомата (бекенд)
- Аутентификация: `ATMController.StartSession(card, pin)` → `IBankingService.Authenticate` (реализация `BankingServiceClient` проверяет PIN, читает/создаёт счет и дневные лимиты).
- Снятие: `ATMController.Withdraw(session, amount)` → `BankingServiceClient.ExecuteWithdrawal` (баланс, суточный лимит) → `CashDispenser.CanDispense` / `TryDispense` (уменьшение остатка диспенсера).
- Логи: `OperationJournal.Add` фиксирует `WITHDRAWAL` (маска карты, сумма, статус) в `storage/operations.json` через `LocalStorage`.
- Чек: опционально, сценарий может вызвать `ReceiptPrinter.PrintReceipt`.

## Основной успешный сценарий (backend-only)

1. Сценарий (в Main или вызывающей системе) знает карту и PIN, вызывает `StartSession(card, pin)`.
2. Бекенд проверяет сумму: валидность, кратность, верхние/нижние лимиты (можно расширить).
3. `Withdraw(session, amount)` запрашивает списание в `BankingServiceClient.ExecuteWithdrawal`; при успехе командует `CashDispenser.TryDispense`.
4. Журнал фиксирует операцию (успех, сумма, маска карты).
5. Опционально инициируется печать чека.
6. Возвращается результат операции вызывающей стороне.

##  Расширения (или альтернативные потоки)

### *а. В любой момент клиент может отменить операцию (до выдачи наличных).
1. Клиент нажимает кнопку "Отмена".
2. Если средства еще не списаны, система отменяет транзакцию.
3. Система отображает "Операция отменена".
4. Возврат в главное меню.

### *б. При каждом выходе системы из строя.
1. Система фиксирует состояние транзакции в энергонезависимой памяти.
2. При восстановлении система проверяет: были ли списаны средства, но не выданы наличные.
3. Если да:
   - Система инициирует процесс компенсации (возврат средств на счет).
   - Система уведомляет службу поддержки.
4. Система регистрирует инцидент в журнале ошибок.

### 3а. Некорректная сумма (некратна 100, ≤0, > 40000)
1. `Withdraw` возвращает отказ; журнал пишет ошибку валидации.

### 5а. В банкомате недостаточно наличных
1. `CashDispenser.CanDispense` возвращает false; журнал пишет ошибку.

### 5а. В банкомате недостаточно наличных для выдачи запрошенной суммы.
1. Система отображает сообщение "Недостаточно наличности в банкомате. Попробуйте меньшую сумму."
2. Система регистрирует событие низкого остатка для службы инкассации.
3. Система предлагает ввести другую сумму или вернуться в меню.
4. Возврат к шагу 2.

### 6а. Банковская система недоступна.
1. Система ожидает ответ 10 секунд.
2. Система отображает "Связь с банком временно недоступна. Попробуйте позже."
3. Система предлагает выбрать другую операцию или завершить сессию.

### 7а. Недостаточно средств на счете клиента.
1. Банковская система возвращает код ошибки "Insufficient funds".
2. Система отображает "Недостаточно средств на счете."
3. Система предлагает ввести меньшую сумму или проверить баланс.
4. Возврат в главное меню или к шагу 2.

### 7б. Превышен суточный лимит снятия.
1. Банковская система возвращает код ошибки "Daily limit exceeded".
2. Система отображает "Превышен суточный лимит снятия (10,000 руб.)."
3. Система показывает доступную для снятия сумму в рамках лимита.
4. Система предлагает ввести меньшую сумму или отменить операцию.
5. Возврат в главное меню или к шагу 2.

### 10а. Ошибка при списании средств (повторяющаяся ошибка банковской системы).
1. Банковская система возвращает ошибку.
2. Система отображает "Ошибка обработки транзакции. Операция отменена."
3. Система регистрирует ошибку с деталями для расследования.
4. Возврат в главное меню.

### 11а. Диспенсер не может выдать купюры (застревание купюр, неисправность).
1. Диспенсер сообщает об ошибке выдачи.
2. Система инициирует откат транзакции в банковской системе (возврат средств на счет).
3. Система отображает "Временная неисправность. Средства не списаны. Обратитесь в банк если деньги были списаны."
4. Система помечает банкомат как требующий обслуживания.
5. Система регистрирует инцидент для службы технической поддержки.
6. Завершение сессии.

### 16а. Печать чека не требуется/недоступна
1. Сценарий пропускает вызов `PrintReceipt`, операция остаётся залогированной.

### 20а. Ошибка механизма выдачи
1. `TryDispense` вернул false; итог — отказ, лог с деталями; при необходимости вызывающая сторона инициирует компенсацию.

## Специальные требования

- **Производительность:** Время от подтверждения суммы до выдачи наличных не должно превышать 15 секунд в 95% случаев.
- **Безопасность:** Вся коммуникация с банковской системой должна быть зашифрована по протоколу TLS 1.3 или выше.
- **Надежность:** Система должна обеспечить устойчивость к сбоям на любом этапе транзакции с возможностью отката.
- **Номиналы:** Банкомат выдает купюры номиналом 100, 500, 1000, 5000 рублей. Приоритет выдачи: максимальные номиналы.
- **Лимиты:**
  - Минимальная сумма снятия: 100 рублей
  - Максимальная сумма за транзакцию: 40,000 рублей
  - Суточный лимит снятия: 10,000 рублей (может варьироваться по типу карты)
- **Интерфейс:** Экран должен показывать прогресс операции (проверка баланса → списание → выдача).
- **Логирование:** Все транзакции с отметкой времени, номера карты, суммы, результата должны сохраняться локально и синхронизироваться с центральной системой.
- **Время ожидания:** Таймаут ввода пользователя: 60 секунд на каждом шаге.

## Список технологий и типов данных

**3а.** Сумма снятия вводится через цифровую клавиатуру или сенсорный экран. Тип данных: положительное целое число, кратное 100, в диапазоне [100; 40,000].

**5а.** Диспенсер оснащен датчиками для подсчета купюр и проверки остатка. Используются механические счетчики или оптические датчики.

**6а.** Запрос в банковскую систему выполняется по протоколу HTTPS/REST или использует специализированный банковский протокол (ISO 8583).

**7а.** Проверка лимитов выполняется на стороне банковской системы с использованием бизнес-правил, хранящихся в базе данных.

**11а.** Диспенсер может использовать технологии компаний Wincor Nixdorf, Diebold, NCR и др.

**18а.** Чек печатается на термопринтере шириной 80мм с логотипом банка, QR-кодом для верификации транзакции.

## Частота использования
Очень высокая. Снятие наличных — основная функция банкомата (примерно 60-70% всех транзакций).

## Открытые вопросы

- Должна ли система предлагать стандартные суммы (быстрый выбор) для ускорения операции?
- Нужно ли поддерживать снятие наличных со связанных счетов (сберегательный, кредитный)?
- Требуется ли подтверждение суммы перед финальным списанием?
- Должна ли система отображать остаток на счете после снятия?
- Нужно ли уведомлять клиента по SMS о каждой транзакции снятия?
- Следует ли ограничить количество попыток снятия в рамках одной сессии?
- Какую стратегию выдачи купюр использовать (минимизация количества купюр, равномерное расходование номиналов)?

# Контракты системных операций

## Операция: withdrawCash(accountId: AccountId, amount: decimal): WithdrawalResult

### Ссылки
Прецеденты: Снятие наличных

### Предусловия
- Клиент успешно аутентифицирован
- `accountId` существует и принадлежит аутентифицированному клиенту
- `amount > 0` и `amount % 100 == 0` (кратно 100)
- `amount <= 40000` (не превышает максимум за транзакцию)
- Банковская система доступна
- Диспенсер в рабочем состоянии

### Постусловия

**Успешный сценарий:**
- Запрос к банковской системе на проверку баланса выполнен (взаимодействие с внешней системой)
- Баланс счета `accountId` уменьшен на `amount` (модификация баланса в банковской системе)
- Суточный лимит снятия для `accountId` увеличен на `amount` (модификация лимита)
- Остаток наличных в диспенсере уменьшен на `amount` (модификация состояния)
- Транзакция зарегистрирована в журнале с типом "WITHDRAWAL", временной меткой, `accountId`, `amount` (создание записи)
- Возвращается `WithdrawalResult.Success` с деталями транзакции
- Бухгалтерская система уведомлена о транзакции (асинхронное взаимодействие)

**Альтернативные сценарии:**
- Если баланс < amount: возвращается `WithdrawalResult.InsufficientFunds`, баланс не изменен
- Если суточный лимит превышен: возвращается `WithdrawalResult.DailyLimitExceeded`, баланс не изменен
- Если диспенсер не может выдать: возвращается `WithdrawalResult.DispenserError`, транзакция откачена, баланс восстановлен
- Если банковская система недоступна: возвращается `WithdrawalResult.SystemError`, состояние не изменено
- Все ошибочные сценарии логируются (создание записи ошибки)

## Операция: checkCashAvailability(amount: decimal): bool

### Ссылки
Прецеденты: Снятие наличных

### Предусловия
- Диспенсер инициализирован
- `amount > 0`

### Постусловия
- Выполнена проверка остатка купюр в диспенсере (чтение состояния оборудования)
- Если `availableCash >= amount`: возвращается `true`
- Если `availableCash < amount`: возвращается `false` и регистрируется событие "LOW_CASH" для службы инкассации (создание события)
- Состояние системы не изменено (операция только для чтения)

## Операция: dispenseCash(amount: decimal): bool

### Ссылки
Прецеденты: Снятие наличных

### Предусловия
- `checkCashAvailability(amount)` вернула `true`
- Диспенсер в рабочем состоянии
- Транзакция подтверждена банковской системой

### Постусловия
- Команда на выдачу купюр отправлена диспенсеру (взаимодействие с оборудованием)
- Купюры выданы в лоток для клиента (физическое действие)
- Внутренний счетчик наличных уменьшен на `amount` (модификация атрибута)
- Если выдача успешна: возвращается `true`
- Если ошибка механизма: возвращается `false`, регистрируется событие "DISPENSER_JAM" для технической службы (создание события)
- Операция выдачи залогирована с деталями: количество купюр по номиналам (создание записи)

## Операция: printWithdrawalReceipt(transactionDetails: WithdrawalTransaction): bool

### Ссылки
Прецеденты: Снятие наличных

### Предусловия
- Транзакция снятия выполнена успешно
- Принтер в рабочем состоянии
- В принтере есть бумага

### Постусловия
- Чек сформирован с данными: дата/время, номер банкомата, замаскированный номер карты, сумма снятия, комиссия (если есть), остаток в банкомате (создание объекта чека)
- Команда на печать отправлена принтеру (взаимодействие с оборудованием)
- Если печать успешна: возвращается `true`
- Если принтер недоступен: возвращается `false`, регистрируется событие "PRINTER_ERROR" (создание события)
- Операция печати залогирована (модификация лога)
