# Прецедент: Проверить баланс

## Рамки
Бекенд банкомата NextGen: локальное JSON-хранилище, без внешних API.

## Уровень
User Goal.

## Основной исполнитель
Клиент (активная сессия банкомата).

## Заинтересованные лица
- **Клиент.** Узнать текущий остаток.
- **Банк/оператор.** Журналировать обращение к счету.

## Предусловия
- Сессия активна: `AtmSession` получен через `StartSession(card, pin)`.
- Счет существует в локальном хранилище (создается при первой аутентификации карты).
- Локальное хранилище доступно.

## Постусловия
- Баланс счета получен из локальных данных.
- В `storage/operations.json` добавлена запись `CHECK_BALANCE` со статусом `Success`.
- Чек печатается только если его вызовет внешний сценарий через `ReceiptPrinter`.

## Логика банкомата (бекенд)
- `ATMController.CheckBalance(session)` вызывает `BankingServiceClient.GetBalance`.
- `BankingServiceClient.GetBalance` читает баланс из словаря `_accountBalances`; при отсутствии записи возвращает `0`.
- `OperationJournal.Add` фиксирует операцию (маска карты, сумма, статус).

## Основной успешный сценарий (backend)
1. Сценарий вызывает `ATMController.CheckBalance(session)`.
2. `GetBalance` возвращает decimal-баланс.
3. `OperationJournal` пишет `CHECK_BALANCE / Success`.
4. Сценарий при необходимости печатает чек (`ReceiptPrinter.PrintReceipt`).
5. Баланс возвращается вызывающей стороне.

## Альтернативы
- Ошибки ввода не обрабатываются: метод принимает готовую сессию.
- При отсутствии счета в хранилище возвращается `0` и всё равно логируется как `Success`.

## Системные операции (факт кода)
- `ATMController.CheckBalance(session) : decimal` — получение баланса и лог.
- `BankingServiceClient.GetBalance(accountId) : decimal` — чтение из памяти/JSON.
- `OperationJournal.Add(OperationEntry)` — запись в `storage/operations.json`.
- `ReceiptPrinter.PrintReceipt(text)` — опционален, не вызывается контроллером.

## Специальные требования (реализованные/ограничения)
- Маскирование номера карты в журнале.
- Нет сетевых вызовов; все данные лежат в `storage/`.
- Идемпотентность: повторный запрос лишь логирует еще одну запись.

## Частота использования
Высокая по бизнес-смыслу; в демо вызывается дважды из `Main`.

## Открытые вопросы
- Нужно ли сигнализировать, что баланс возвращен как 0 из-за отсутствия записи?
- Нужен ли кэш/троттлинг для частых запросов?
- Печатать ли чек автоматически?
