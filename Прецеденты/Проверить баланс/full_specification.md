# Прецедент: Проверка баланса

## Рамки
Система банкомата (ATM) NextGen для обслуживания клиентов банка.

## Уровень
Задача, определенная пользователем (User Goal).

## Основной исполнитель
Клиент банка.

## Заинтересованные лица и их требования

**Клиент.** Хочет быстро и безопасно проверить остаток на своем счете. Хочет получить точную информацию о доступных средствах для планирования покупок. Желает иметь возможность получить чек с балансом для документального подтверждения.

**Банк.** Хочет обеспечить безопасный доступ к информации о счете только авторизованным клиентам. Заинтересован в точности отображаемой информации. Хочет минимизировать нагрузку на банковскую систему при частых запросах баланса.

**Банковская система.** Хочет получать корректно сформированные запросы на получение баланса. Заинтересована в защите от несанкционированного доступа.

**Оператор банкомата.** Хочет минимизировать количество обращений клиентов по поводу некорректно отображенного баланса.

## Предусловия
- Клиент вставил карту в банкомат
- Клиент успешно прошел аутентификацию (ввел правильный PIN)
- Банковская система доступна

## Результаты (Постусловия)
- Клиент получил информацию о текущем балансе счета
- Запрос на баланс зарегистрирован в системе логирования
- Опционально: чек с информацией о балансе распечатан

## Логика банкомата (бекенд)
- Запрос баланса: `ATMController.CheckBalance(session)` → `IBankingService.GetBalance` (реализация `BankingServiceClient` читает баланс из локального хранилища).
- Логи: `OperationJournal.Add` пишет `CHECK_BALANCE` (маска карты, сумма, статус) в `storage/operations.json`.
- Чек: опционально вызывающей стороной через `ReceiptPrinter.PrintReceipt`.

## Основной успешный сценарий (backend-only)
1. Сценарий вызывает `CheckBalance(session)`.
2. `BankingServiceClient.GetBalance` возвращает актуальный баланс.
3. `OperationJournal` фиксирует `CHECK_BALANCE` (маска карты, сумма, статус).
4. При необходимости вызывается `ReceiptPrinter.PrintReceipt`.
5. Баланс возвращается вызывающей стороне.

## Расширения (или альтернативные потоки)

### 2а. Банковская система недоступна/ошибка
1. `GetBalance` возвращает ошибку/исключение; журнал пишет отказ; вызывающая сторона решает, что делать (повтор/завершение).

### 6а. Чек не требуется/принтер недоступен
1. `PrintReceipt` не вызывается или возвращает false; баланс уже залогирован, сценарий завершается.

## Специальные требования

- Время ответа на запрос баланса: ≤ 3 секунд в 95% случаев.
- Маскирование номера карты в логах и чеке.
- Логирование каждой операции с временной меткой.

## Список технологий и типов данных

**1а.** Баланс отображается в рублях (RUB) с использованием символа валюты или текста.

**2а.** Запрос к банковской системе выполняется по протоколу HTTPS с использованием REST API или SOAP.

**3а.** Идентификатор счета передается в виде GUID или зашифрованного токена.

**6а.** Ввод подтверждения печати чека осуществляется через клавиатуру банкомата или сенсорный экран.

**8а.** Чек печатается на термопринтере шириной 80мм.

## Частота использования
Очень высокая. Это одна из наиболее часто используемых операций в банкомате (примерно 40-50% всех транзакций).

## Открытые вопросы

- Должна ли система отображать доступный кредитный лимит вместе с балансом?
- Нужно ли показывать отдельно заблокированные средства (холды)?
- Требуется ли отображение баланса бонусных/накопительных счетов?
- Должна ли система предлагать SMS-уведомление с балансом?
- Нужно ли сохранять историю запросов баланса на самом банкомате для быстрого доступа?
- Следует ли ограничить количество запросов баланса в рамках одной сессии?

# Контракты системных операций

## Операция: getBalance(accountId: AccountId): decimal

### Ссылки
Прецеденты: Проверка баланса

### Предусловия
- Клиент успешно аутентифицирован
- `accountId` существует и принадлежит аутентифицированному клиенту
- Банковская система доступна

### Постусловия
- Запрос к банковской системе выполнен (взаимодействие с внешней системой)
- Получен актуальный баланс счета (возврат значения типа `decimal`)
- Операция залогирована с отметкой времени и идентификатором клиента (модификация лога)
- Если операция успешна: возвращается значение баланса с точностью до копеек
- Если ошибка: возвращается исключение `BankingServiceException`

## Операция: printBalanceReceipt(accountId: AccountId, balance: decimal): bool

### Ссылки
Прецеденты: Проверка баланса

### Предусловия
- Баланс успешно получен из банковской системы
- Принтер находится в рабочем состоянии
- В принтере есть бумага

### Постусловия
- Чек сформирован с данными: дата/время, номер банкомата, замаскированный номер карты, баланс (создание объекта чека)
- Команда на печать отправлена принтеру (взаимодействие с оборудованием)
- Операция печати залогирована (модификация лога)
- Если печать успешна: возвращается `true`
- Если принтер недоступен или нет бумаги: возвращается `false` и регистрируется ошибка
- Чек содержит временную метку текущего момента (использование системного времени)
