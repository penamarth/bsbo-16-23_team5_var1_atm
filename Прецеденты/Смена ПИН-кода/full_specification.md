# Прецедент: Смена PIN-кода

## Рамки
Бекенд банкомата NextGen: локальное JSON-хранилище, простая проверка старого PIN без политик и шифрования.

## Уровень
User Goal.

## Основной исполнитель
Клиент (активная сессия/есть карта и старый PIN).

## Заинтересованные лица
- **Клиент.** Поменять PIN и получить подтверждение.
- **Банк/оператор.** Зафиксировать факт смены.

## Предусловия
- Клиент уже аутентифицирован старым PIN (или старый PIN известен вызывающей стороне).
- Карта привязана к счету (создается при `Authenticate`).
- Локальное хранилище доступно.

## Постусловия
- **Успех:** значение PIN для карты в `bank_card_pins.json` заменено на новый; запись `CHANGE_PIN/Success` добавлена в `operations.json`.
- **Отказ:** PIN не изменен; запись `CHANGE_PIN/Failed` с подробностью "Смена PIN отклонена".
- Чек не печатается автоматически.

## Логика банкомата (бекенд)
- `ATMController.ChangePin(cardData, oldPin, newPin)` → `BankingServiceClient.ChangePin`.
- `BankingServiceClient.ChangePin`:
  - читает сохраненный PIN по номеру карты;
  - сравнивает с `oldPin`; при несовпадении возвращает `false`;
  - при успехе перезаписывает новый PIN, сохраняет JSON-файлы.
- `OperationJournal.Add` логирует операцию (маска карты, статус).

## Основной успешный сценарий (backend)
1. Сценарий знает `cardData`, `oldPin`, `newPin`.
2. Вызывает `ATMController.ChangePin(...)`.
3. `ChangePin` делегирует в `BankingServiceClient.ChangePin`.
4. Сервис валидирует старый PIN, сохраняет новый, persist.
5. `OperationJournal.Add` пишет `CHANGE_PIN / Success`.
6. Сценарий может продолжить сессию или завершить ее.

## Альтернативы
- Старый PIN неверен → `BankingServiceClient.ChangePin` возвращает `false`, журнал `Failed`.
- Новый PIN не проверяется на формат/политику (ограничение текущей версии).

## Системные операции (факт кода)
- `ATMController.ChangePin(card, oldPin, newPin) : bool` — оркестрация и лог.
- `BankingServiceClient.ChangePin(card, oldPin, newPin) : bool` — сравнение и запись в JSON.
- `OperationJournal.Add(OperationEntry)` — запись `CHANGE_PIN`.

## Специальные требования (реализованные/ограничения)
- Маскирование номера карты в журнале.
- Нет шифрования PIN и политики сложности.
- Нет ограничения попыток.

## Частота использования
Низкая; в демо вызывается один раз из `Main`.

- Требуется ли ограничение попыток/таймаут?
- Нужны ли уведомления клиенту после смены PIN?
