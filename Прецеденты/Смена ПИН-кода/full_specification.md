# Прецедент: Смена PIN-кода

## Рамки
Система банкомата (ATM) NextGen для обслуживания клиентов банка.

## Уровень
Задача, определенная пользовател ем (User Goal).

## Основной исполнитель
Клиент банка.

## Заинтересованные лица и их требования

**Клиент.** Хочет быстро и безопасно изменить PIN-код своей карты для повышения безопасности. Желает простую процедуру смены PIN без посещения отделения банка. Хочет быть уверенным, что новый PIN надежно сохранен в системе.

**Банк.** Хочет обеспечить безопасный процесс смены PIN с защитой от перехвата. Заинтересован в том, чтобы клиенты регулярно меняли PIN. Хочет предотвратить использование простых или скомпрометированных PIN-кодов.

**Банковская система.** Хочет получать зашифрованные запросы на смену PIN. Заинтересована в валидации нового PIN по политикам безопасности. Хочет аудировать все изменения PIN.

**Служба безопасности.** Хочет отслеживать частоту смены PIN для выявления подозрительной активности. Заинтересована в предотвращении социальной инженерии.

## Предусловия
- Клиент вставил карту в банкомат
- Клиент успешно прошел аутентификацию (ввел текущий правильный PIN)
- Банковская система доступна

## Результаты (Постусловия)
- PIN-код карты изменен в банковской системе
- Клиент получил подтверждение успешной смены
- Операция смены PIN залогирована в системе аудита
- Старый PIN деактивирован
- Новый PIN активирован немедленно

## Логика банкомата (бекенд)
- Инициатор: сценарий вызывает `ATMController.ChangePin(cardData, oldPin, newPin)` (UI отсутствует).
- Проверка и сохранение: `BankingServiceClient.ChangePin` сверяет старый PIN и обновляет новый в локальном хранилище (`LocalStorage`).
- Логи: `OperationJournal.Add` фиксирует `CHANGE_PIN` (маска карты, статус) без раскрытия PIN.

## Основной успешный сценарий (backend-only)
1. Сценарий имеет карту и старый/новый PIN.
2. Вызывает `ATMController.ChangePin(card, oldPin, newPin)`.
3. `BankingServiceClient.ChangePin` валидирует старый PIN и сохраняет новый.
4. `OperationJournal` фиксирует результат `CHANGE_PIN`.
5. Возвращается статус операции.

## Расширения (или альтернативные потоки)

### 5а. Новый PIN не проходит политику/совпадает со старым
1. `ChangePin` возвращает отказ (PolicyViolation/SameAsOld), журнал пишет ошибку.

### 10а. Банковская система недоступна/отклоняет запрос
1. `ChangePin` возвращает SystemError/BankRejected; PIN не изменён; журнал — Failed.

### 17а. Печать подтверждения не требуется/недоступна
1. `PrintReceipt` не вызывается; операция остаётся залогированной.

## Специальные требования

- **Безопасность:**
  - Новый PIN должен передаваться в банковскую систему только в зашифрованном виде (AES-256 или RSA).
  - PIN не должен отображаться на экране в открытом виде (использовать «****»).
  - PIN не должен сохраняться в логах в открытом виде.
  - Клавиатура для ввода PIN должна быть защищена от скимминга (шифрованная PIN-pad).

- **Политика PIN:**
  - PIN состоит ровно из 4 цифр.
  - Запрещены простые комбинации: 0000, 1111, 2222, ..., 9999, 1234, 4321, 0123.
  - PIN не должен совпадать с последними 4 цифрами номера карты.

- **Производительность:**
  - Время от подтверждения нового PIN до получения подтверждения от банка: не более 5 секунд в 95% случаев.

- **Удобство:**
  - Максимум 3 попытки ввода подтверждающего PIN.
  - Таймаут ввода: 60 секунд на каждом шаге.

- **Аудит:**
  - Все попытки смены PIN логируются, включая неуспешные.
  - Логи содержат: timestamp, идентификатор карты (замаскированный), номер банкомата, результат операции.

## Список технологий и типов данных

**4а.** Ввод PIN осуществляется через зашифрованную PIN-pad клавиатуру (EPP - Encrypted PIN Pad). PIN зашифровывается аппаратно внутри устройства.

**5а.** Проверка на простые PIN выполняется локально на банкомате для ускорения процесса. Используется предопределенный список запрещенных комбинаций.

**9а.** Шифрование PIN для передачи: Triple DES, AES-256, или RSA в зависимости от стандартов банка. Используется протокол DUKPT (Derived Unique Key Per Transaction) для генерации уникальных ключей шифрования.

**10а.** Запрос в банковскую систему может использовать протокол ISO 8583 (для банкоматных сетей) или HTTPS/REST API с payload в зашифрованном виде.

**16а.** Журнал аудита хранится локально на банкомате в защищенной энергонезависимой памяти и синхронизируется с центральной системой раз в час или по требованию.

## Частота использования
Низкая. Клиенты меняют PIN нечасто (примерно 1-2% транзакций), но это критически важная операция для безопасности.

## Открытые вопросы

- Должна ли система требовать ввод старого PIN перед вводом нового для дополнительной безопасности? (Сейчас клиент уже аутентифицирован).
- Нужно ли отправлять SMS/email уведомление клиенту после успешной смены PIN?
- Следует ли ограничить количество смен PIN в день (защита от атаки перебора)?
- Должна ли система блокировать карту после нескольких неуспешных попыток смены PIN?
- Нужно ли требовать более строгие правила для PIN (например, запрет повторяющихся пар цифр)?
- Должен ли новый PIN активироваться немедленно или с задержкой (для защиты от мошенничества)?
- Следует ли хранить историю использованных PIN (запрет повторного использования последних N PIN)?

# Контракты системных операций

## Операция: changePin(cardData: CardData, oldPin: Pin, newPin: Pin): ChangePinResult

### Ссылки
Прецеденты: Смена PIN-кода

### Предусловия
- Клиент успешно аутентифицирован с `oldPin`
- `cardData` валидна и принадлежит текущей сессии
- `newPin` состоит из 4 цифр
- `newPin != oldPin` (новый PIN отличается от старого)
- Банковская система доступна

### Постусловия

**Успешный сценарий:**
- Новый PIN валидирован локально на соответствие политике (проверка правил)
- `newPin` зашифрован с использованием аппаратного шифрования PIN-pad (преобразование данных)
- Запрос на смену PIN отправлен в банковскую систему с зашифрованным `newPin` и идентификатором карты (взаимодействие с внешней системой)
- Старый PIN деактивирован в базе данных банка (модификация данных в банковской системе)
- Новый PIN активирован и связан с `cardData` (модификация данных в банковской системе)
- Операция смены PIN залогирована в журнале аудита с записью: timestamp, замаскированный номер карты, номер банкомата, результат "SUCCESS" (создание записи аудита)
- Возвращается `ChangePinResult.Success`

**Альтернативные сценарии:**
- Если `newPin` не соответствует политике (простой PIN): возвращается `ChangePinResult.PolicyViolation`, PIN не изменен
- Если `newPin == oldPin`: возвращается `ChangePinResult.SameAsOld`, PIN не изменен
- Если банковская система отклонила запрос: возвращается `ChangePinResult.BankRejected`, PIN не изменен
- Если банковская система недоступна: возвращается `ChangePinResult.SystemError`, PIN не изменен
- Все ошибки логируются в журнал аудита с результатом "FAILED" и кодом ошибки (создание записи ошибки)

## Операция: validatePinPolicy(pin: Pin): bool

### Ссылки
Прецеденты: Смена PIN-кода

### Предусловия
- `pin` состоит из 4 цифр

### Постусловия
- PIN проверен на соответствие списку запрещенных комбинаций: [0000, 1111, 2222, ..., 9999, 1234, 4321, 0123, 9876] (чтение предопределенного списка)
- Если PIN не в списке запрещенных: возвращается `true`
- Если PIN в списке запрещенных: возвращается `false`
- Состояние системы не изменено (операция только для чтения)

## Операция: verifyPinMatch(pin1: Pin, pin2: Pin): bool

### Ссылки
Прецеденты: Смена PIN-кода

### Предусловия
- `pin1` и `pin2` состоят из 4 цифр

### Постусловия
- Выполнено посимвольное сравнение `pin1` и `pin2` (операция сравнения)
- Если `pin1 == pin2`: возвращается `true`
- Если `pin1 != pin2`: возвращается `false`, счетчик ошибок ввода инкрементирован (модификация счетчика)
- Если счетчик ошибок >= 3: генерируется событие "MULTIPLE_PIN_MISMATCH" (создание события)
- Состояние PIN не изменено (операция проверки)

## Операция: encryptPinForTransmission(pin: Pin): EncryptedPin

### Ссылки
Прецеденты: Смена PIN-кода

### Предусловия
- `pin` валиден (4 цифры)
- PIN-pad устройство готово к работе

### Постусловия
- PIN зашифрован аппаратно внутри PIN-pad с использованием Triple DES или AES (аппаратное шифрование)
- Использован уникальный ключ шифрования, сгенерированный по алгоритму DUKPT (генерация ключа)
- Возвращается `EncryptedPin` - байтовый массив зашифрованных данных
- Оригинальный PIN удален из оперативной памяти после шифрования (очистка памяти)
- Операция шифрования залогирована (без указания PIN) (создание записи лога)
