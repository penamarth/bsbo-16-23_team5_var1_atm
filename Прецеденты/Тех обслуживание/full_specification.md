# Прецедент: Техническое обслуживание и инкассация

## Рамки
Бекенд банкомата NextGen: локальная логика без интерфейса, операции обслуживания выполняются напрямую через `MaintenanceController`, данные о сервисном коде и лимитах не хранятся.

## Уровень
User Goal.

## Основной исполнитель
Техник / инкассатор.

## Заинтересованные лица
- **Техник/инкассатор.** Пополнить диспенсер, изъять принятые средства, увидеть состояние устройств.
- **Банк/оператор.** Контролировать остатки и журналировать действия (сейчас только через лог).

## Предусловия
- Физический доступ к банкомату и знание сервисного кода.
- Код обслуживания равен константе `"9999"` (хранится в коде).
- Локальное хранилище и устройства доступны.

## Постусловия
- При успешной аутентификации можно:
  - увеличить остаток диспенсера (`CashDispenser.Refill`);
  - изъять все накопленные средства из купюроприемника (`CashAcceptor.CollectAllCash`);
  - получить сводку состояния устройств (`CheckStatus`).
- Все действия логируются через `Logger` (не в `OperationJournal`).
- При неверном коде ничего не меняется, пишется предупреждение.

## Логика банкомата (бекенд)
- `MaintenanceController.AuthenticateCollector(code)` сравнивает ввод с константой `"9999"`, пишет успех/предупреждение в `Logger`.
- `RefillDispenser(amount)` проверяет `amount > 0`, увеличивает `_remaining` диспенсера и логирует новый остаток.
- `CollectAcceptor()` обнуляет накопленную сумму купюроприемника и возвращает изъятое значение.
- `CheckStatus()` выводит в лог состояние диспенсера и статусы устройств (статично «готов» для прочих).

## Основной успешный сценарий (backend)
1. Техник вызывает `AuthenticateCollector(code)`.
2. При `true` выполняет нужные действия: `RefillDispenser(amount)`, `CollectAcceptor()`, `CheckStatus()`.
3. Логи фиксируют все операции.

## Альтернативы
- Неверный код → `AuthenticateCollector` возвращает `false`, предупреждение в лог, операции не выполняются.
- Некорректная сумма пополнения (`amount <= 0`) → предупреждение в лог, остаток не меняется.

## Системные операции (факт кода)
- `AuthenticateCollector(code) : bool`
- `RefillDispenser(amount) : void`
- `CollectAcceptor() : decimal`
- `CheckStatus() : void`

## Специальные требования (реализованные/ограничения)
- Нет блокировки при многократных неверных кодах.
- Нет проверки емкости диспенсера/купюроприемника.
- Логи обслуживания не сохраняются в журнал операций.

## Частота использования
Низкая; демонстрационный вызов есть в `Main`.

## Открытые вопросы
- Нужны ли лимиты емкости и блокировки при ошибочных кодах?
- Следует ли писать события обслуживания в `OperationJournal`?
- Должна ли константа кода храниться в защищенном хранилище?
