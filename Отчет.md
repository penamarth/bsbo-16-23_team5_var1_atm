# Отчет по практической работе №1
## Модельно-ориентированный подход к проектированию

## Краткое описание
Разработана информационная система банкомата (ATM) с применением UML-диаграмм и принципов Domain-Driven Design (DDD). Реализованы как базовые функции (снятие наличных, проверка баланса), так и расширенные (смена PIN, внесение наличных, перевод средств, обслуживание).

## Архитектура проекта

Проект организован по принципу **Bounded Contexts** (Ограниченных контекстов):

### Структура папок

## Особенности реализации

### 1. DDD подход
Применен подход Domain-Driven Design с разделением на Bounded Contexts:
- **Hardware Context**: Управление физическим оборудованием
- **Banking Context**: Интеграция с банковской системой
- **Operation Context**: Бизнес-логика клиентских операций
- **Maintenance Context**: Логика обслуживания и инкассации
- **Kernel**: Общие компоненты (Value Objects, UI, Logging)

### 2. Builder Pattern
Использован паттерн Builder для конструирования `ATMController` с валидацией зависимостей через рефлексию.

### 3. Dependency Injection
Все зависимости передаются через конструктор, обеспечивая слабую связанность и тестируемость.

### 4. Расширяемость
Новые способы оплаты, устройства или операции могут быть добавлены без изменения существующего кода благодаря использованию интерфейсов.

## Контрольные вопросы

**1. Что такое UML? Какие вы знаете основные диаграммы UML?**

UML (Unified Modeling Language) — это унифицированный язык моделирования для визуализации, спецификации, конструирования и документирования артефактов программных систем.

Основные диаграммы UML:
- **Структурные**:
  - Диаграмма классов (Class Diagram)
  - Диаграмма компонентов (Component Diagram)
  - Диаграмма развертывания (Deployment Diagram)
  - Диаграмма объектов (Object Diagram)
  - Диаграмма пакетов (Package Diagram)

- **Поведенческие**:
  - Диаграмма вариантов использования (Use Case Diagram)
  - Диаграмма последовательности (Sequence Diagram)
  - Диаграмма деятельности (Activity Diagram)
  - Диаграмма состояний (State Machine Diagram)
  - Диаграмма коммуникаций (Communication Diagram)

**2. Какие элементы входят в состав диаграммы классов?**

Диаграмма классов состоит из:

**Основные элементы:**
- **Классы**: Прямоугольники с тремя секциями (имя, атрибуты, операции)
- **Интерфейсы**: Классы со стереотипом `<<interface>>`
- **Абстрактные классы**: Имя класса выделено курсивом

**Отношения:**
- **Ассоциация (Association)**: Сплошная линия (связь между классами)
- **Агрегация (Aggregation)**: Линия с пустым ромбом (отношение "целое-часть", слабая связь)
- **Композиция (Composition)**: Линия с закрашенным ромбом (отношение "целое-часть", сильная связь)
- **Обобщение/Наследование (Generalization)**: Линия с незакрашенной стрелкой (иерархия классов)
- **Реализация (Realization)**: Пунктирная линия с незакрашенной стрелкой (реализация интерфейса)
- **Зависимость (Dependency)**: Пунктирная линия со стрелкой (один класс использует другой)

**Дополнительные элементы:**
- **Пакеты**: Группировка классов
- **Перечисления (Enums)**: Специальные типы
- **Стереотипы**: Метки вида `<<stereotype>>`
- **Видимость**: `+` public, `-` private, `#` protected, `~` package
- **Множественность**: Указание количества связанных объектов (1, 0..1, 1..*, *)
